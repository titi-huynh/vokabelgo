3. IMPLEMENTATION DETAILS
-------------------------
a) may-home-motion.js (New UMD module):
   - buildSheetLayoutFromMeasuredManifest(): Validates 16-frame measured JSON manifest
     (referenceHeight: 278, directions: down/right/up/left, cols: 0..3, positive bounds,
     valid anchorX/anchorY); computes common scale (150 / 278) across all 16 frames;
     throws explicit errors on missing or malformed metadata.
   - resolveDirectionFromVector(): Resolves physical displacement vector (dx, dy)
     to cardinal facing using dominant axis with 0.18 hysteresis threshold to prevent
     near-diagonal jitter; retains current direction when displacement <= 1e-4.
   - computeWalkFrame(): Distance-based 4-gait frame chooser with ~76px stride
     (stepLen = 19px), alternating contact (0, 2) and passing (1, 3) frames.
     Preserves active contact pose (0 or 2) when stopping.

   - Outside of this insertion, all original bytes, encoding, and newlines were preserved.

c) may-home-game.js:
   - Loaded assets/may-home-game/may-walk-directions-v1.png and
     assets/may-home-game/may-walk-directions-v1.json via Promise.all with image + fetch.
   - Safely catches any asset load/parse failures into existing clickable scene/nav
     fallback rather than fake front walking.
   - Renders 4-direction frames using actual source crop bounds and local anchors at
     common scale 150 / 278, without horizontal mirroring, whole-sprite bob, or squash.
   - Facing updates on physical displacement during walking and holds final facing upon
     stop or arrival (no forced front pose reset).
   - Removed waveUntil on automatic arrival; preserved original still/wave atlas

   - Consistent low-motion instant jumps and safe cancellation of arrivals on drag/nav interruptions.
